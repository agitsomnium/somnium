# 후원회원 유입 흐름 · 검토본 (2026-11-01)

로컬 검토본(http://127.0.0.1:8766/ , /guide/). 운영 홈페이지·외부 호스팅·가입 개방·메일 발송·결제·권한은 바꾸지 않았다.

## 1. 이번에 만든 것

| 항목 | 내용 | 파일 |
|---|---|---|
| 가입 전 안내 | 후원이 이어 가는 활동, 월 1만 원 이상 혜택, 대표 시리즈 6개, 추천 입문 순서, 공개/회원 전용 구분, 4단계 흐름, FAQ | `supabase/web/guide/guide-data.json`, `build_guide.py`, `guide.css` |
| 경로 선택 | 강의실 첫 화면에 ‘처음 / 이미 가입 / 수강 코드’ 세 길. 후원 확인 전 안내에 후원 안내 링크 | `index.html`, `app.js`, `member.css` |
| 검토 서버 | `/guide/` 라우트 추가 (원천 JSON은 서빙하지 않음) | `serve.py` |
| 시험 | 안내 빌드 6개, 서버 경계 1개 추가 | `test_guide.py`, `test_serve.py` |

공개용 빌드는 `python3 supabase/web/build_guide.py --mode public` 이다. 강사 공개 허락이 `pending`인 항목(강사 이름)은 공개 빌드에서 빠지고, 검토 빌드에서는 빨간 점선 표시가 붙는다.

## 2. 공개 가능한 것과 비공개

- 공개 안내에는 시리즈 이름·연도·주제 한 줄만 쓴다. 영상 주소·ID·썸네일·개별 강의 제목·자료 파일은 넣지 않았다(시험으로 확인).
- 맛보기 영상은 만들지 않았다. 기록상 강사 허락과 자료 범위는 ‘미확정’이다. 허락된 강의가 정해지면 안내 데이터에 항목을 더하는 방식으로 붙인다.
- 강사 이름은 정용택(이미 공개 홈페이지에 노출)만 공개 상태다. 나머지는 제목에서 읽은 이름이라 허락 확인 전 `pending`.
- 시리즈 이름·분류는 연결된 영상 제목에서 만든 임시 분류다. 추천 입문 순서는 제 초안이며 운영진이 정한 것이 아니다.

## 3. 후원 → 강의 이용 흐름

홈페이지 참여·후원(기존) → **새로 `/guide/`** → 한빛누리 CMS 정기후원(외부) → 강의실 회원가입(이메일 OTP) → 후원 확인 요청 → 운영진이 한빛누리 내역 대조 후 확인 → 강의 이용.
기존 회원은 로그인, 세미나 수강 코드 이용자는 로그인 후 코드 등록 칸을 쓴다(기존 권한 로직 변경 없음).

운영 홈페이지에 반영하려면 기존 `참여·후원`의 후원 카드 위에 `/guide/` 링크(또는 같은 내용)를 넣어야 한다. 이번에는 하지 않았다.

## 4. 가입 입력 최소안 (제안, 적용 안 함)

현재: 이름·생년월일·휴대전화 필수(DB `not null`, 관리자 화면에 표시), 동의 1개.
확인한 사실: 후원 확인은 사람이 한빛누리 내역과 이름·이메일로 대조한다. 생년월일·전화를 쓰는 자동 절차는 코드에 없다. 기부금 영수증은 한빛누리가 발급한다.

제안:
1. 필수: 이메일(OTP로 확인) + 이름(한빛누리 후원자명과 다르면 입력하는 ‘후원자명’ 선택 칸 포함).
2. 생년월일: 받지 않음. 영수증·본인확인은 한빛누리 몫이다. 필요해지는 운영 절차가 있으면 그때 선택 입력으로.
3. 전화번호: 선택. 동명이인·대조 불가 때 연락용으로만.
4. 적용하려면 DB 마이그레이션(두 칸 nullable)·가입 화면·관리자 표시를 바꿔야 하고, 개인정보 보유·삭제 기간 문안도 같이 정해야 한다. 법적 필수 여부는 판단하지 않았다. 사람이 결정.

## 5. 측정안 (숫자는 채우지 않음)

기준일을 정해 시작 전 값을 한 번 동결하고, 이후 같은 정의로 센다. 현재 회원수·목표는 조회·가정하지 않았다.

| 단계 | 정의 | 출처 |
|---|---|---|
| 신규 후원회원 | 기간 안에 처음 ‘후원 확인(qualified)’이 된 계정 수 | DB 후원 상태 이력 |
| 안내 도달 | `/guide/` 방문 | 운영 호스팅 도입 뒤에야 가능. 지금은 측정 수단 없음(개인정보 없는 집계만 검토) |
| 가입 이탈 | 가입 시작 대비 프로필 완료, 완료 대비 후원 확인 요청 | 계정·요청 시각 |
| 확인 지연 | 요청 → 확인 소요 시간 | 이력 |
| 실제 강의 이용 | 확인 후 N일 안에 강의 재생 요청이 1회 이상인 후원회원 | resource RPC 호출 기록(현재 이력 저장 여부 미확인) |
| 후원 유지 | 확인 후 3·6개월 시점에 후원 자격이 종료되지 않은 비율 | 자격 이력 + 한빛누리 대조(사람) |

필요한 것: 이용·유지 집계는 이력 테이블 확인·보강이 선행이다. 이름 단위 개인 추적 대신 집계 숫자만 쓴다.

## 6. 미확인·결정 필요

- 운영 호스팅(외부 접근 제한 포함)·신규 가입 개방·OTP 메일 발송 한도·봇 방지.
- 실제 아이폰 시험, 신규 일반회원 OTP 재로그인, 기관 DB·Storage 독립 복원.
- 강사 공개·맛보기 허락 범위, 시리즈별 편수 최종 확정(검토 중 계산은 94, 기록은 93이라 안내에는 총 93만 사용).
- 후원회원 북클럽 참가비 혜택은 공개 홈페이지 표시만 보았고 내용을 확인하지 못해 안내에서 뺐다.
- 생년월일·전화 최소안 채택 여부, 추천 순서 확정, 홈페이지 링크 반영 시점.
- 후원 확인 소요 시간 약속 문구는 넣지 않았다.
