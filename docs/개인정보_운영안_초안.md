# 솜니움 후원회원 강의실 · 개인정보 운영안 (초안, 2026-11-02)

코드·원격 시험 DB와 대조해 작성했다. 법률 자문이 아니다. 아래 «법적 근거» 칸은 일반 원칙만 적었고 조문·기한은 기관이 확인해야 한다.

## 1. 실제 수집·저장·처리 (코드 및 원격 시험 DB 대조)

| 항목 | 필수 | 저장 위치 | 쓰임 | 비고 |
|---|---|---|---|---|
| 이메일 | 필수 | Supabase Auth (`auth.users`) | 인증번호 로그인, 후원 확인 대조 | 인증번호 메일은 Gmail SMTP(agit.somnium)로 발송 |
| 이름 | 필수 | `classroom_private.profiles.name` | 관리자 화면 표시, 후원 확인 대조 | |
| 전화 | 선택 | `profiles.phone` | 동명이인·대조 불가 때 연락 | 형식 검사만 함 |
| 후원자명 | 선택 | `profiles.supporter_name` | 한빛누리 후원자명이 가입 이름과 다를 때 대조 | |
| 동의 기록 | 필수 | `profiles.consent_version/consent_at` | 동의 문안 버전·시각 | |
| 후원 확인 상태 | 자동 | `supporters` (상태·확인자·시각) | 강의 이용 권한 | 후원 금액·계좌는 저장하지 않음 |
| 수강 코드 이용권 | 자동 | `series_entitlements`, `code_attempts` | 시리즈 이용 | 코드 원문은 저장하지 않고 해시만 |
| 처리 기록 | 자동 | `audit` (행위자 UUID·행위·대상) | 운영진 처리 이력 | 이름·이메일 없음(단, 이사 명단 등록은 이메일이 대상으로 남음) |
| 로그인 세션 | 자동 | Supabase Auth 내부 (`auth.sessions`) | 로그인 유지 | IP·기기 정보를 포함할 수 있음(시험 DB에서 IP 1종 확인) |
| 생년월일 | **수집 안 함** | 컬럼 `birth`만 남음 | — | 현재 값이 있는 행은 1건뿐이며 시험용 가상 프로필 |

쓰지 않는 것: 주민번호, 결제정보, 계좌, 주소. 결제·기부금 영수증은 한빛누리가 처리한다.

처리 서비스: Supabase(DB·인증·파일, 서울 리전) · Google(Gmail SMTP 발송, YouTube 재생) · Vimeo(일부 영상 재생) · 호스팅 사업자(Cloudflare 예정; 접속 로그) · 한빛누리(후원 접수, 별도 처리자).
현재 실제 회원 개인정보는 없다. 시험 계정 3개(관리자 시험 프로필 1, 시험 회원 2)뿐이라 지금이 정책을 정하기 가장 쉬운 때다.

## 2. 발견한 결함 (이번에 고침: 초안 SQL, 미적용)

원격 시험 프로젝트에서 시험 계정을 삭제해 보니 **삭제가 HTTP 500으로 실패했다.** 후원 확인을 요청하면 `audit`에 그 사람 행이 생기는데 `audit.actor`가 사용자에 매여 삭제를 막는다(`series_entitlements`도 같음). 즉 후원 확인 요청을 한 회원은 지금 구조로는 탈퇴 처리를 할 수 없다.
- 초안 `supabase/proposed/20261102_member_erasure_DRAFT.sql`: 관리자가 일반 회원 한 명을 한 번에 삭제(`somnium_erase_member`). 프로필·후원 요청·이용권·인증 계정을 지우고, 처리 기록에서는 행위자를 비우고 대상 값을 `erased`로 바꾼다. 관리자·승인자·코드 발급자·본인은 거부한다.
- 격리 PostgreSQL 시험 PASS(`member-erasure-pg.log`): 삭제 전 방식이 실패하는 것 재현, 비관리자 거부, 대상 외 회원 불변, 감사 기록에 개인정보 없음.
- 원격 적용은 하지 않았다. 관리자 화면 «회원 삭제» 단추도 아직 없다(적용 승인 뒤 추가).

## 3. 추천 운영안 (기관 결정 필요 항목은 §4)

1. **수집 최소화:** 이름·이메일 필수, 전화·후원자명 선택, 생년월일 미수집. 동의 화면에 항목·목적·보유기간·문의처·거부 시 불이익(가입 불가)을 적는다.
2. **탈퇴·삭제 요청:** 회원이 agit.somnium@gmail.com으로 요청 → 본인 확인(가입 이메일로 회신) → 관리자가 삭제 처리 → 처리 후 회신. 목표는 요청 후 7일 이내. 법정 기한은 확인 필요.
3. **보유 기간:** 가입 정보는 탈퇴 즉시 삭제. 후원이 종료되고 1년간 접속이 없으면 안내 메일 후 삭제(추천). 법령상 의무 보존이 있다고 확인된 항목은 없다. 후원금 회계 자료는 한빛누리·솜니움 회계 규정에 따르며 이 강의실에 저장하지 않는다.
4. **처리 기록:** 개인 식별 값을 쓰지 않는 UUID·행위만 1년 보관, 이후 삭제.
5. **백업:** 암호화 백업을 월 1회, 최근 3개만 보관한다(약 3개월 후 자동 소멸). 삭제 요청분은 백업에서 즉시 지우지 않고 만료로 소멸시키되, 백업을 복원할 때는 «삭제 장부(UUID와 삭제일)»를 다시 적용한다. 이 장부에는 이름·이메일을 넣지 않는다.
6. **기존 생년월일:** 실제 회원 값이 없으므로 신규 가입 개방 전에 시험 프로필 1건의 값을 비우고, 이후 컬럼을 제거하는 마이그레이션을 따로 만든다.
7. **처리방침 공개:** 가입 화면과 `/guide/`에 링크. 위탁·국외 이전 해당 여부(Supabase, Google)는 기관이 확인해 문안에 반영한다.

## 4. 기관 결정이 필요한 항목 (한 번에)

| # | 결정 | 추천 | 이유 |
|---|---|---|---|
| 1 | 개인정보 책임자·문의 담당 이름과 메일 | 이름 지정 + agit.somnium@gmail.com | 처리방침에 반드시 적어야 하고 코드로 정할 수 없음 |
| 2 | 후원 종료·미접속 후 보유 | 1년 뒤 안내 후 삭제 | 회원 수가 작은 동안 관리 부담이 적고 최소 보관 원칙에 맞음 |
| 3 | 시험 프로필 1건의 생년월일 비우기 | 승인 | 실회원이 아니고 수집 중단 방침과 일치 |
| 4 | 백업 암호 보관자와 보관 위치 | 암호 보관자 2인 + 기관 소유 Drive/계정 | 한 사람 부재 시 복구 불가를 막음 |
| 5 | 호스팅 계정 소유자(Cloudflare) | 솜니움 이름의 기관 계정 | 서비스 소유가 개인이면 인계가 어려움 |
| 6 | 삭제 마이그레이션 원격 적용 시점 | 가입 개방 전 | 개방 후에는 삭제 불가 회원이 생김 |

## 5. 2026-11-02 현황 갱신 (결정 4·5 관련)

- 호스팅: Cloudflare 계정은 agit.somnium@gmail.com 이름의 기관 계정이고 Zero Trust 무료로 보호 중이다(결정 5는 «이 계정을 소유자로 확정하느냐»만 남음).
- 백업: 암호화 백업 1건이 기관 Drive `강의실_백업`(소유 agit.somnium, 제한 공유)에 있고 내려받아 지문이 일치했다. **암호 복호화 비밀은 이 맥 키체인에만 있다.** 두 번째 보관 담당과 기관 소유 비밀 보관 경로는 정해지지 않았다 — 결정 4가 닫히기 전에는 «기관이 독립적으로 복구할 수 있다»고 말하지 않는다.
- 삭제 SQL은 여전히 초안이며 원격 미적용이다.
