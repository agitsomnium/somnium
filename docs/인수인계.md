# 솜니움 홈페이지 인수인계

2026-10-18 시작. 이 문서는 간사와 다음 대표가 함께 사용합니다. 현재 계정 생성·시트 생성·Pages 공개·도메인 연결은 하지 않았습니다.

## 간사는 어디서 고치나요?

솜니움 구글계정이 소유하는 시트를 엽니다. 시트 주소는 사람이 생성한 뒤 이 문서에 추가합니다. 한 프로그램을 여러 줄에 복사해 두지 말고, 기존 ID의 줄을 고칩니다. 첫 줄의 칸 이름과 순서는 바꾸지 않습니다. ID는 영어 소문자·숫자·하이픈으로 적으며 공개 뒤에는 유지합니다.

탭과 칸의 정본은 [시트 설계](시트_설계.md)입니다. 공개 탭에는 신청자의 이름·연락처·비공개 자료·회계·계정 정보를 적지 않습니다. 숨겨진 줄도 공개 CSV 원문에는 포함될 수 있습니다. 「공개=아니오」는 개인정보를 보호하는 기능이 아닙니다.

## 세미나 한 건은 어떻게 등록하나요?

1. 강사진 탭에 강사의 ID·이름·확인된 소개를 적습니다. 기존 강사는 새 줄을 만들지 않습니다.
2. 세미나 탭에 새 ID, 제목, 소개, 상태, 강사진_id를 적습니다. 강사가 여러 명이면 `teacher-a;teacher-b`처럼 잇습니다. 날짜와 장소가 확정되지 않았으면 비워 둡니다.
3. 회차 탭에 각 회차를 한 줄씩 적고 세미나_id를 동일하게 연결합니다.
4. 신청할 수 있는 프로그램만 확인된 구글폼 URL을 넣습니다. 기존 다른 프로그램의 폼을 재사용하지 않습니다.
5. 공개할 줄에 「예」를 넣습니다. 공개할 세미나가 참조하는 강사진과 회차도 함께 확인합니다.
6. 다음 날 자동 갱신 뒤 실제 사이트에서 제목·날짜·신청 링크를 확인합니다. 급하면 관리자에게 수동 갱신을 요청합니다. 간사는 GitHub 로그인이 필요 없습니다.

## 수정·취소·종료는 어떻게 하나요?

수정: 같은 ID의 제목·소개·날짜·장소를 고칩니다. 회차 자료와 영상도 같은 ID로 이어집니다.

취소: 상태를 「취소」로 바꾸고 취소사유를 적습니다. 페이지와 자료는 남고 신청 버튼은 사라집니다. 이미 신청한 사람에게 알리는 일은 기존 신청 관리 절차로 사람이 처리합니다.

종료: 상태를 「종료」로 바꿉니다. 신청 버튼을 숨기고 기록을 계속 보여 줍니다. 프로그램 줄을 삭제하지 않습니다. 숨길 때는 공개를 「아니오」로 바꾸고, 연결된 회차·영상도 함께 숨깁니다. 잘못 연결되면 빌드가 중단됩니다.

## 사이트가 바뀌지 않으면 어떻게 하나요?

하루 갱신은 한국 시각 오전 6시가 목표지만 GitHub 작업 대기 때문에 늦을 수 있습니다. 먼저 입력 날짜와 공개 값을 확인한 뒤 관리자에게 요청합니다. 관리자는 저장소 Actions의 「시트에서 홈페이지 만들기」에서 실패 이유를 확인합니다. 잘못된 입력·다운로드 실패 때는 새 사이트를 올리지 않고 기존 공개본을 유지합니다. 고친 뒤 Run workflow로 다시 실행합니다. 자동 갱신 실패 알림 수신자는 관리자 2명이 설정합니다.

## 관리자는 처음에 무엇을 설정하나요?

GitHub 조직과 공개 저장소는 사람이 만듭니다. 관리자 2명을 지정하고 각자 2단계 인증과 복구 수단을 확인합니다. 시트는 agit.somnium@gmail.com 소유로 만들고 여섯 탭만 웹에 게시합니다. 각 탭의 CSV URL을 `config/sheets.json`에 넣습니다. 로그인·공유 화면 주소가 아닌 공개 CSV 주소가 필요합니다.

로컬 확인은 `python3 scripts/build.py --sample`입니다. 실제 시트는 `python3 scripts/fetch_sheets.py` 다음 `python3 scripts/build.py --data data/live`로 검사합니다. `SITE_BASE_PATH=/저장소명`을 넣으면 조직 프로젝트 Pages의 하위 경로에 맞춥니다. 조직 홈페이지 저장소라면 빈 값입니다.

공개 활성화: 사람이 자료·디자인·도메인과 배포 권한을 확인한 뒤 GitHub Settings의 Pages에서 Actions를 선택하고, 저장소 변수 `PAGES_ENABLED=true`와 필요한 `SITE_BASE_PATH`를 설정합니다. 준비 단계의 기본값은 공개 배포 금지입니다. 샘플 데이터로 Pages를 배포하지 않습니다.

## 고정 글과 이미지도 바꿀 수 있나요?

소개·이사회·연혁·오시는 길·기획강좌·아지트·후원 안내는 `content/`의 Markdown입니다. 자주 바꾸는 목록만 시트에 둡니다. 고정 글 변경은 관리자에게 요청합니다. 원문 출처와 확인 날짜를 문서 안에 남깁니다. 이미지 교체 때는 대체 텍스트와 사용 권한도 확인합니다.

## 대표가 바뀔 때 무엇을 넘기나요?

| 대상 | 넘길 것 | 실제 확인 |
|---|---|---|
| GitHub | 조직 관리자 2명, 저장소, Actions 알림 | 새 대표가 로그인·수동 갱신 |
| 구글 | 조직 계정 소유, 시트·폼 편집 권한, 복구 담당 | 새 간사가 시험 프로그램 등록·수정·취소 |
| 도메인 | 솜니움 명의, 등록업체, 갱신일·결제 책임 | 연락처·2단계 인증·자동갱신 확인 |
| 영상 | 두 채널 관리자, 일부공개 URL 목록 | 관리자가 원본 영상을 재생 |
| 자료 | 우피 백업, 고정 글, 최종 시안, 검증 기록 | 백업을 열고 파일 수·해시 확인 |
| 외부 안내 | 구글폼·후원 링크, 문의 담당 | 폼과 후원 안내를 실제로 열기 |

비밀번호와 복구 코드는 기관이 정한 별도 보관 수단으로 넘깁니다. 공개 저장소·시트·이 문서에는 넣지 않습니다. 개인 Supabase·Cloudflare 계정은 사이트 운영에 필요하지 않습니다.

## 새 사이트 확인 뒤 무엇을 하나요?

사람이 도메인을 결제하고 DNS를 연결합니다. 휴대폰과 PC에서 프로그램·신청·후원·지도·지난 자료를 확인한 뒤 Pages 공개를 승인합니다. 새 사이트가 정상인 것을 확인한 후 우피를 해지합니다. 노션 원본과 백업은 보존합니다. 과거 우피 주소는 새 도메인으로 자동 이동시킬 수 있는지 우피 해지 전에 확인합니다.

## 강의 초안은 어디에 있나요?

`docs/transcripts/`와 `docs/lecture-drafts/`는 검수 전 작업 폴더이며 공개 산출물 `dist/`에 넣지 않습니다. 일부공개 영상 주소를 공개 영상 탭에 옮기면 인터넷 전체에 노출됩니다. 강사·운영진 확인 전에는 공개 탭에 넣지 않습니다.


## 현재 디자인을 이어 고치려면

사용자 피드백으로 최초 세리프 저널을 보류하고 전면 재구성했습니다. 디자인시스템_적용.md가 현재 선택·토큰·출처를 설명합니다. A는 차콜·푸른 강조의 질문 중심 화면, B는 밝은 편집형입니다. 최종 디자인 채택은 사람 차례입니다. 색·본문/제목 위계는 assets/site.css, HTML 구성은 scripts/render.py에서 관리합니다. 북클럽 포스터는 book-october / book-november의 ID와 연결돼 있습니다. 새 북클럽의 포스터를 바꾸려면 관리자에게 이미지와 ID를 전달합니다.

## 밝기 선택과 네 페이지 완성 (2026-10-18)

사용자가 A+B를 밝기 선택으로 확정했습니다. 이제 A안의 구조가 모든 화면에 공통이며, 머리말의 어둡게/밝게 버튼으로 색만 바뀝니다. 선택은 브라우저에 저장되어 이동·새로고침·새 탭에서도 이어집니다. 저장이 차단돼도 현재 화면의 선택은 작동합니다.

네 하위 페이지는 scripts/pages.py, 화면 구성과 공통 머리말은 scripts/render.py, 밝기 동작은 assets/theme.js, 하위 페이지 스타일은 assets/pages.css입니다. 디자인 토큰은 assets/site.css의 색 변수에 있습니다. 고정 글은 기존대로 content/ Markdown에서 고칩니다. 글의 원본·출처와 사람 확인 경계는 유지합니다.

현재 주소: 연구소 소개 /about/, 프로그램 /programs/, 연구자료 /resources/, 참여·후원 /participate/. 세미나 상세는 /seminars/{id}/입니다. 책모임의 book-{id} 앵커는 홈의 포스터 링크와 연결되므로 ID를 유지합니다.

홈·네 페이지·세미나 상세의 24화면, 밝기 유지·다른 탭 동기화·저장 차단·키보드 조작을 실제 브라우저로 확인했습니다. 새 공개 영상은 시트 영상 탭에 넣으면 연구자료와 관련 세미나 상세에 나타납니다. 현재 영상별 URL은 인계를 기다립니다.
