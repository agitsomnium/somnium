## 1. PDF 반복 다운로드 — 끊기는 단계 (증거: `download-stages.txt`)
- 단계별 훅(서버 응답 → Blob → 다운로드 시작(`a[download]` 클릭, `userActivation.isActive=true`) → 파일 저장)으로 구분했다.
- **끊기던 탭(이전 시험 탭):** 서버 200 `application/pdf` → Blob 정상 → 앵커 클릭까지 정상, 그러나 Chrome 다운로드 기록과 `~/Downloads`에 항목 없음. 앱과 무관한 작은 텍스트 blob 대조 버튼도 같은 탭에서 3회 모두 저장 안 됨, **새 탭에서는 3회 모두 저장됨** → 끊김은 앱이 아니라 «Chrome이 다운로드 항목을 만드는 단계의 탭 상태». 그 탭은 내가 사용자 활동 없는 프로그램 클릭으로 첫 다운로드를 만든 뒤 상태가 바뀐 시험 탭이다. Chrome 내부 규칙의 세부는 확정하지 못했다. 사용자 다운로드 설정·보안은 건드리지 않았다.
- **새 탭, 실제 클릭, 배포본:** 서로 다른 PDF 2건(선정안 84,899B / 연재 427호 443,609B)과 같은 PDF(선정안) 재다운로드 모두 저장. `file`·`pdfinfo`·`pdftotext` 열림, sha256이 `series-coupons-20261101/materials-source-manifest.json` 등록 지문과 일치(선정안 두 사본 동일 `1fdd2957277604cc`). 최종 빌드(`edda5ff3`)에서도 제6강 1건 재확인(`08ac87dc6fcea79e` 일치) 및 시작 안내 문구 표시 확인.
- 사용자 안내: 시작 시 «…내려받기를 시작했습니다. 파일이 저장되지 않으면 브라우저 주소창의 다운로드 허용 안내를 확인해 주세요.» (앱이 저장 여부는 알 수 없음).
- 한계: 사용자가 처음 겪은 실패의 원인이 배경 새로고침 취소였는지·이 탭 상태였는지는 재현하지 못해 확정하지 않는다(둘 다 방지 또는 안내 반영).

## 2. 30초 갱신에서 패널 유지 (회귀 시험: `catalogView.test.js`)
- 새로고침마다 목록을 통째로 다시 그리던 것을 «같은 사용자·같은 행이면 그대로 둠(keep) / 행·사용자 변경 시 다시 그림(render) / 로그아웃·권한 회수 시 즉시 비움(clear)»으로 나눴다. 다시 그릴 때도 열린 자료 패널을 복원하고 스크롤 위치를 되돌린다. `clearPrivate()`는 열린 패널 기록·서명도 비운다.

- 배포본 실측(새 탭, 로그인): 자료 패널 열고 스크롤 1378에서 약 70초(갱신 2회: `me`·`catalog` RPC 2세트 관찰) 후 PDF 버튼 5개, 열린 시리즈 1개, 스크롤 1378 유지. 로그아웃 후 강의 단추 0(이전 빌드 실측, `clearPrivate` 경로 불변).
- 미검증: 권한 회수 라이브 시험(실회원·시험 승인 변경을 하지 않음) — 순수 판단 함수 시험으로 대체.
