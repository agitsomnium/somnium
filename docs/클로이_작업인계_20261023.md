## 2. 확정된 선택

- **최종 디자인은 A안 구조에 B안 밝기 선택이다.** 이것이 사용자의 최종 선택이다. 레이아웃은 A로 공통이고, 머리말의 어둡게/밝게 버튼으로 색만 바뀐다. 초기값은 어두운 화면이고 마지막 선택을 우선한다.
- **"최종 디자인 채택은 사람 차례"는 원문 `docs/인수인계.md`의 오래된 서술이라 무효다.** 디자인 재선택을 사람에게 되묻지 않는다.
- 최초 세리프 저널안은 보류 상태이며 다시 채택할 필요가 없다.
- 실제 디자인 토큰은 다음과 같다.
  - 서체: Pretendard, 본문 400, 제목 800
  - 어두운 화면 바탕: 차콜 `#1b1c1e`
  - 밝은 화면 바탕: 종이색 `#f1f0e9`
  - 강조색: 푸른 계열
- `/a/`가 확인 대상이다. `/b/`는 비교용이며 초기 밝기만 다르다.
- 인프라 원칙은 다음과 같다.
  - 기관 조직 GitHub의 공개 저장소와 Pages를 쓴다.
  - 데이터는 기관 구글시트의 공개 CSV로 운영하고, 간사는 시트만 만진다.
  - 고정 글은 `content/`의 Markdown으로 관리한다.
  - 개인 Supabase·Cloudflare 사이트에는 의존하지 않는다.
  - 원문에 나온 다른 저장소는 읽기 전용이다.

## 5. 재개 명령

프로젝트 폴더에서 실행한다.

```bash
cd ~/web/somnium
git status                      # 현재 fatal이 정상. 바뀌었으면 기록
python3 scripts/build.py --sample
python3 scripts/build.py --sample --output design/a --base /a
python3 scripts/build.py --sample --output design/b --base /b --theme b
python3 -m unittest discover -s tests -v
python3 -m http.server 8876 --bind 127.0.0.1 --directory design
```

- 서버를 띄운 뒤 `http://127.0.0.1:8876/a/`를 브라우저로 연다. `/b/`는 비교용이다.
- 포트가 이미 쓰이면 다른 포트를 쓰고 그 사실을 기록한다.
- 빌드와 시험의 결과는 이번 세션에서 새로 얻은 값만 "오늘 확인"으로 적는다.
- 기본 빌드는 `dist/`, 위의 `--output` 명령은 각 비교 미리보기를 갱신한다. 서버는 `design/`을 제공한다.
- `scripts/fetch_sheets.py`와 `--data data/live` 빌드는 사람이 시트 URL을 채운 뒤에만 실행한다. 공란 상태에서는 실행하지 않는다.

## 6. 우선순위

1. **상태 복원.** `hub.시작`으로 현재 상태를 확인하고 이 문서와 대조한다. 위 5번 명령으로 오늘 기준 빌드·시험·화면을 확인하고 Hub 기록을 남긴다.
2. **실제자료 누락표 정리.** 아래 항목마다 보유/없음/사람 확인 필요를 표로 만든다.
   - 시트 여섯 탭 URL
   - 강사진 약력
   - 프로그램별 신청 링크
   - 일부공개 영상 URL
   - 날짜·장소
   - 후원·신청 링크의 실제 작동
   - 건물 사진 사용 권한과 대체 텍스트
   - 도메인
   - 관리자 2명
3. **브라우저 재검증.** 10/18 근거를 현재 상태로 갱신한다. 최소한 홈과 네 하위 페이지의 두 밝기, PC와 모바일을 본다.
4. **백업 해시 재검증.**
5. **실운영 준비.** 사람이 만든 기관 시트의 여섯 공개 CSV URL을 받아 연결한다. 실데이터 빌드를 검증하고 계정·배포 승인 경계에서 사람에게 넘긴다. 간사는 GitHub에 들어가지 않고 시트만 편집한다.

## 7. 강의 정리글은 별도 대기

시즌1 일부공개 회차별 영상 URL이 없어 자막 확보와 글 생성은 시작하지 않았다. 자막은 실제 강의의 논지와 인용 구간을 확인할 원천이다. URL을 받으면 한국어 자동자막 수집 → Python 중복 정리·분할 → 시험 2건 → 원문 대조 → 본 배치 순으로 진행한다. 약력은 확인된 자료로만 작성한다. 각 초안에는 원본 링크와 「강사 확인 전」을 표시하고, 강사·운영진 확인 전 공개 빌드에 넣지 않는다. 일부공개 URL을 공개 시트에 넣는 것도 공개 행위다.

원문 `docs/강의초안_대기.md`의 10/19 제출·10/21 크레딧 만료는 이미 지난 조건이다. 재개 전에 새 일정·예산과 실제 이용 가능한 모델·가격을 확인한다. 당시 강의 작업 API 지출 $0 기록은 이번 인계 문서 생성 호출비와 별개다. 이번에는 강의 생성이나 배치 제출을 하지 않았다.

현재 모델 운영 지침은 Hub `프로모션API_사용법_v1`과 `~/bin/클로드API`를 우선 확인한다. 키는 키체인에서 스크립트 내부로만 읽고 출력·파일·로그에 기록하지 않는다. 과거 대기 문서의 모델·요금·키 만료를 현재 사실로 재사용하지 않는다.

## 8. 사람 차례 — 원인별

- **기관 소유권:** 기관 명의 GitHub 조직·공개 저장소와 관리자 2명, 기관 구글계정의 시트·폼·채널 권한을 사람이 준비한다. 시트는 설계만 완료했고 생성하지 않았다.
- **실제 운영 자료:** 확정 일정·장소·강사진 약력·프로그램별 신청 폼·영상 URL을 운영진이 제공·확인한다. 샘플의 진행 상태를 10/23 현재 행사 상태로 간주하지 않는다.
- **비용·외부 공개:** 계정 생성·도메인 결제·DNS 연결·Pages 공개·우피 해지는 실행하지 않는다. 준비와 검증 결과를 제시한 뒤 사람이 확인한다. 새 사이트 정상 운영 후 우피 해지를 진행한다.
- **도메인:** somnium-agit.org / somnium-research.org / somnium-korea.org는 10/18 후보다. `docs/도메인_후보.md`의 가격·미등록 조회 결과는 당시 값이며 구매 직전 다시 조회한다.
- **자료 공개:** 강의 초안·일부공개 URL은 공개 승인 뒤 반영한다. 회계 공개는 고유번호 전환 뒤 별도 단계다.

우피 백업과 이전 시안은 보존한다. 「솜니움 정보정리.pdf」는 계정 정보가 있어 열지 않는다. 길섶·한예연 저장소는 읽기만 한다. 이번 인계로 홈페이지 코드·계정·공개 상태를 바꾸지 않았다.
